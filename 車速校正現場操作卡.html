車速校正現場操作卡

替相機設「可信的測速校正」,讓超速能正確、準確開單。現場只做必填即可運作,其餘欄位留空一律吃系統預設。

政策 「只信校正來源開單」預設開啟 —— 沒校正的相機不會開速度單(速度仍顯示、仍記錄,只是不開單)。
待校正相機 cam 2 台62 基隆段隧道口 cam 8 62 交通流量 其餘相機超速未啟用,不需處理
最省事做法

只畫 trip-wire 兩線 ＋ 填車道編號 ＋ 兩線實距 ＋ 速限,其餘全部留空吃預設即可。

方法 A · Trip-wire 跨線

建議 · 最準
  1. 現場量兩線實距
    沿行車方向選兩個橫斷位置,建議相隔 8–15 公尺(太近時間差小、太遠會出鏡)。用皮尺/測距輪量出實際公尺數並記下(例 10.0)。兩位置須垂直車流、車輛直行通過、相機都看得清楚。
  2. 畫兩條線
    網頁 → 選相機 → 車速設定 → 開啟 ROI 編輯器。
    類型選 speed_line_in,點 2 點畫過近端橫斷位置。儲存時系統強制跳出兩欄:填 車道編號(例 1)＋兩線實距(m)(填步驟 1 量到的數,例 10)。
    類型改 speed_line_out,畫過遠端位置,儲存時填相同車道編號與距離。
    多車道:每車道各一組 in/out,車道編號不同(1、2、3…)。
  3. 設速限
    回車速設定頁,填 speed_limit 速限與 overspeed_kmh 容許超速(預設 10,即超過「速限＋10」才開單)。
  4. 存檔重啟
    按 完成(儲存並重啟服務),偵測會重讀新設定。

方法 B · Homography 4 點

替代 / 補強 · 路口彎道可用
  1. 畫車速區(4 點梯形)
    ROI 編輯器畫一個 speed_roi,4 點梯形罩住一段車道。
  2. 填實際寬長
    該區填 calibration_width_m(車道實寬,台灣約 3.5m,以現場為準)＋ calibration_length_m(梯形涵蓋路面實長,量出來)。
  3. 或一鍵自動校正
    按 自動校正(消失點) 產生 4 點＋寬長。⚠ 用的是假設值(3.5m / 10m),務必用下方「驗證」量誤差,必要時改回真實寬長。
  4. 存檔重啟
    4 點＋寬＋長齊 → 標籤顯示 Homography 啟用 → 按 完成(儲存並重啟)。

最少必填 vs 選填

留空 = 自動用預設
欄位必填?留空時的預設
Trip-wire 兩線 in/out ＋ 車道編號 ＋ 兩線實距必填(A 方式)無預設,缺了不觸發
Homography 4 點 ＋ 寬 ＋ 長必填(B 方式)可按自動校正帶假設值(寬 3.5m / 長 10m)

進階參數(平滑因子 / 離群 / 採樣數 / Track 逾時…)選填各有預設(0.35 / 2.0 / 5 / 5s…),現場不用動
speeding_require_calibrated 只信校正來源開單選填開(True)—— 沒設定一律視為只信校正來源

驗證

必做 · 確認真的準
  1. 開精度校正記錄
    該相機偵測功能設定裡打開 精度校正記錄 開關 → 存檔並重啟。
  2. 收 ≥ 30 台跨線車
    讓現場真實車流跑一段時間,收集至少 30 台跨越 trip-wire 的車。
  3. 產生報告並判讀
    車速設定頁「4. 精度校正報告」→ 按 產生／更新報告。判讀三點如下:
n > 0「已校正 (homography)」或 trip-wire 那組有值且 n 大於 0 —— 代表校正生效。修復前因舊 bug 恆為 n=0,現在出現才算對。
MAE平均絕對誤差越小越好。偏差 bias:正 = 系統高估、負 = 低估。
建議係數「純 pixel」組若列出建議係數,可按 套用建議係數 自動填回 speed_kmh_per_pxps。
$ python scripts/speed_calibration_report.py

畫了卻不動?常見狀況

症狀原因處理
畫了線卻不開單in/out 車道編號沒配對,或距離沒填重畫(現在會強制填車道＋距離)
速度全空 (NULL)未校正 ＋「只信校正來源開單」開著照卡片校正,或臨時關該開關
速度飆到 100+ 不合理純 pixel 抖動偽值改用 trip-wire 或 homography
報告「已校正」組 n=0沒有生效的 homography / trip-wire檢查 4 點＋寬長是否齊、或兩線是否配對
臨時 某台暫時無法校正又必須開單:車速設定頁把「只信校正來源開單」關掉 → 恢復純 pixel 開單(準確度低、可能誤開,僅臨時)。
