## 三、三個 🔴 的實情

### 3.1 出口滯留（exitQueue）— 是「現場沒設 ROI」，不是「做不到」

87 現場四台相機的 zone 實查（2026-09-02）：

| 相機 | 壅塞 zone | direction 值 |
|---|---|---|
| cam2 | 上/下高速公路前後平面道路 | `straight` |
| cam3 | 上匝道前停等區、下匝道後平面道路 | `INOUT` / `straight` |
| cam4 | 車流區 1、高速下匝道 | `straight` / `INOUT` |
| cam5 | 車流區 1、下匝道停等區 | `straight` / `INOUT` |

- 我方**已有** IN/EXIT/INOUT 進出線幾何（`stream.py`，車流量統計在用）。
- 但現場 zone **一個都沒標 `EXIT`/出口方向**，壅塞 ROI 全在進口側。
- **結論**：出口滯留需要在出口方向設 ROI。這是**現場設定**問題，不是程式能力問題。匝道場景是否真有「出口滯留」的控制意義，須先確認 —— 若無意義，此欄位標「不適用」即可。

### 3.2 強制切換（forcedSwitchCount）— 屬號誌控制端指標

「動態演算法強制切相位的次數」——這是**動態控制邏輯**的產物，不是純偵測。要等動態控制真正接管配時後才有意義，須在該邏輯裡定義何謂「強制」。

### 3.3 彙整輸出層 — 卡在缺 `/sig` 攝入合約

需要一支服務，把 **壅塞（排隊）+ signal_tc3（燈態/相位）** 按路口彙整成上述 JSON 並送出。目前**未知 `/sig` 怎麼收**：
- HTTP 逆向已試遍 `/stats`、`/aicctv`、`/adaptive`、`/ingest` 等 POST 目標，全 404 → 攝入端點不在此後端或路徑不同。
- actuator / swagger 皆關閉，`.35` SSH 帳密未取得（網頁 Basic 那組非 OS 帳密）。
- **待取得**：`/sig` 後端原始碼 / repo，或攝入合約（是我方 push？還是 `/sig` 來拉？MQTT topic？）。

## 五、可立即動工 vs 需先解阻塞

| 項目 | 依賴 | 可否現在做 |
|---|---|---|
| 路口↔相機對照表、燈態歸納 GREEN/RED | 無 | ✅ 可做 |

| 彙整輸出服務 | `/sig` 攝入合約 | ⛔ 阻塞：缺合約 |

**建議順序**：先做無依賴的兩項（對照表 + 合算），同時去要 `/sig` 攝入合約與現場 zone 方向標記，最後補出口滯留與輸出層。
