# 動態號誌控制 — 父子頁面重構 PLANNING

> 目標：把散落的號誌功能收成**一個父頁 + 子分頁**，新增一頁「即時畫面 × 切換動態」互動比對，
> 並讓特定使用者登入後**只看到動態號誌的全部功能**。
> 建立：2026-09-04。現況問題：功能一路加上去，側邊欄已有 6 個平行項目，彼此看不出是一組。

---

## 〇、先講一個會影響設計的前提

**權限目前存在瀏覽器的 localStorage，而且只有 admin / ops / viewer 三種角色。**

```js
const permissionMatrix = reactive(loadPermissionMatrix());   // ← localStorage
const userRole = ref(localStorage.getItem('user_role') || 'admin');
const isAdmin = computed(() => userRole.value === 'admin');
```

所有號誌頁面都是 `v-if="isAdmin"`。這帶來兩個問題：

1. **做不到「只看到號誌」** —— 沒有這種角色，而且 `isAdmin` 是二元的
2. **選單權限可被使用者自己改** —— 改 localStorage 就能讓選單全開
   （後端 API 仍有 `get_current_user` 把關，所以拿不到資料；但選單顯示不該靠客戶端狀態）

**所以權限必須後端化**，這是本次重構的必要前置，不是附帶項目。詳見第四節。

## 二、★ 新頁：即時畫面 × 切換動態 互動比對

這是本次的核心新功能。目的：**看得出「號誌一切換，排隊怎麼變」**。

### 2.1 版面（三區）

```
┌──────────────────────── 即時總覽 ────────────────────────┐

│  ┌─────────────┐ ┌─────────────┐  ┌──────────────────┐  │
```

### 2.2 為什麼這個版面能回答問題

- **兩台相機並排**：分相1/分相2 各一台（`ramp_timing_baseline.json` 的 `constraint_camera`：ID3／ID4），
  用既有的 `/api/congestion/{id}/stream`（**已含壅塞疊加**，排隊區域直接畫在畫面上）
- **同一條時間軸**：分相色帶 + 兩側排隊曲線疊在一起，**換相的那一刻排隊怎麼轉折**一眼看得到
- **游標連動**：滑過時間軸 → ③ 顯示該時刻的完整決策（成本三項、判定、歧異原因）
  —— 這是「互動效果比對」的核心：不是看兩個靜態數字，是看**因果對應**

### 2.3 資料來源（全部現成，只差一個聚合端點）

| 區塊 | 來源 | 狀態 |
|---|---|---|
| 即時畫面 | `/api/congestion/{camera_id}/stream` | ✅ 現成，含疊加 |
| 燈桿與倒數 | `/api/signal/status` 的 `intersections[]` | ✅ 現成（含 `phase_elapsed_sec`） |
| 即時決策 | `/api/signal/shadow/plan` | ✅ 現成 |
| 時間軸 | **新** `/api/signal/shadow/timeline` | 🔴 要做 |

**`/api/signal/shadow/timeline?minutes=15`** 回壓縮後的平行陣列（不要回物件陣列，15 分鐘 180 筆 × 10 欄會太肥）：

```json
{
  "t0": "2026-09-04T20:30:00", "interval_sec": 5,
  "green_phase": [1,1,1,2,2,...],
  "queue_m_1": [0,7,12,12,5,...],
  "queue_m_2": [47,52,58,58,31,...],
  "ours":   [0,0,1,0,0,...],      // 1 = SWITCH
  "actual": [0,0,0,1,0,...],      // 1 = 該刻偵測到換相
  "agree":  [1,1,0,null,1,...],
  "switch_gain": [...], "keep_gain": [...], "change_cost": [...],
  "reason": [...]                  // 只在歧異的點帶字串,其餘 null
}
```

`reason` 只在歧異點帶字串是刻意的：一致的點不需要理由，全帶會讓回應肥三倍。

### 2.4 實作要點與風險

- **兩路即時串流的頻寬** —— 監控頁已有 `lowBandwidth` 判斷與畫質切換機制，沿用；
  預設用較低碼率，使用者可切高畫質
- **時間軸用純 SVG 畫，不拉圖表庫** —— 三條軌都是簡單的色帶與折線，
  既有的 `st-trend`（運作統計的 CSS 長條）已證明夠用；拉 Chart.js 只為這一張圖不划算
- **游標連動要 throttle** —— `mousemove` 直接更新會太頻繁，用 `requestAnimationFrame` 節流
- **⚠️ 影片與資料的時間不同步** —— 串流有數秒延遲，時間軸是 5 秒取樣。
  **不要假裝它們對得上**：畫面標「即時（約延遲 N 秒）」，時間軸的游標只驅動 ③ 的決策明細，
  不去試圖 seek 影片。硬要對齊會做出一個看起來精確、實際上錯位的東西。

## 三、既有頁面要怎麼搬

**不重寫，只搬位置。** 每個子頁的 template 與 loader 原封不動，改成父頁內的 `v-show`：

```html
<div v-if="page==='signal_hub'">
  <div class="ds-page-hero"> … 父頁 hero + tab 列 … </div>
  <div v-show="signalTab==='overview'"> ★ 新 </div>
  <div v-show="signalTab==='light'">   … 既有燈態頁內容 … </div>
  …
</div>
```

🛑 **用 `v-show` 不用 `v-if`**：`v-if` 會在切 tab 時銷毀重建，
既有頁面裡有輪詢計時器與展開狀態（如 TC3 訊框的 `sigFrameExpanded`），
重建會把它們洗掉。`v-show` 只切 CSS，狀態留著。

🛑 **搬動時 div balance 一定要逐段驗**（CLAUDE.md 的鐵律）：
這次要搬 6 大段，任何一段少一個 `</div>` 都會讓 `#app` 提早關閉。
建議**一次搬一段、每段搬完就跑一次 SOP**，不要六段一起搬。

## 四、權限：讓使用者只看到動態號誌

### 4.1 現況與問題

- 角色只有 `admin` / `ops` / `viewer`，權限矩陣存 **localStorage**
- 號誌頁全部 `v-if="isAdmin"` —— 非 admin 完全看不到，admin 看得到全部
- 使用者改 localStorage 就能讓選單全開（資料仍拿不到，但這個設計不對）

### 4.2 方案

1. **後端回傳權限**：`/api/auth/me` 多回 `role` 與 `permissions`（字串陣列），
   前端 `permissionMatrix` 改成從後端拿，localStorage 只當離線快取
2. **新增權限鍵 `signal`**：涵蓋整個號誌父頁（含所有子分頁）
3. **新增角色 `signal_operator`**：`permissions = ['signal']`，登入後
   `firstAllowedPage()` 直接落在 `signal_hub`，側邊欄只出現那一項
4. 號誌父頁的條件從 `v-if="isAdmin"` 改成 `v-if="hasPerm('signal')"`
   （admin 因為 `hasPerm` 對 admin 一律回 true，行為不變）

### 4.3 子分頁的細分權限（選配，先不做）

「號控下傳」與「設定」有下發風險，未來可再拆 `signal.control` 子權限。
**現在不做** —— 下發本來就有 `SIGNAL_TC3_CONTROL` + `QUERY_ONLY` 兩層後端把關，
前端權限再細分屬於錦上添花，不該擋住這次重構。

## 五、分階段實作順序

| 階段 | 內容 | 驗收條件 |
|---|---|---|
| **P1** | `/api/signal/shadow/timeline` 端點 | 回 15 分鐘壓縮陣列，長度一致、`interval_sec` 正確；歧異點才有 `reason` |
| **P2** | 父頁殼 + tab 列，**先只放一個既有子頁** | div balance、lint 全過；切 tab 不重載、輪詢不中斷 |
| **P3** | 其餘 5 個子頁逐段搬入（**一段一驗**） | 每段搬完 div balance 與 lint 都過；舊側邊欄項目移除 |
| **P4** | ★ 即時總覽頁（三區） | 兩路串流可播；時間軸與游標連動；③ 明細跟著游標更新 |
| **P5** | 權限後端化 + `signal` 權限鍵 + `signal_operator` 角色 | 該角色登入只看到號誌父頁；改 localStorage 無法讓選單全開 |

**P1→P3 不動任何既有功能的行為**，只是換位置；P4 是新增；P5 動到登入流程，最後做。

## 六、明確不做的事

- **不做二層側邊欄選單** —— 這 8 個子頁關聯緊密，tab 更快；二層選單在窄螢幕難用
- **不重寫既有子頁** —— 搬位置就好，重寫等於把已經驗證過的東西再冒一次險
- **不為時間軸拉圖表庫** —— 純 SVG／CSS 夠用
- **不強行同步影片與時間軸** —— 串流有延遲，硬對齊會做出「看起來精確但實際錯位」的東西
- **不細分子分頁權限** —— 下發已有兩層後端把關，前端再細分不急
