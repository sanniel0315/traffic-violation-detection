## 二、裝置資訊

```
VID:PID   0403:6001  FTDI FT232 Serial (UART) IC
by-id     /dev/serial/by-id/usb-FTDI_FT232R_USB_UART_A96TPRFZ-if00-port0
→ 實體    /dev/ttyUSB0        （Bus 001 Device 011）
權限      crw-rw---- root dialout      ubuntu 已在 dialout 群組 ✅
```

⚠️ `.env` 一律寫 **by-id 路徑**，不要寫 `/dev/ttyUSB0` ——
拔插或多接一個轉換器時 ttyUSB 編號會飄移。

## 三、設定變更

```diff
- #LOCK_SERIAL_PORT=/dev/ttyUSB0
+ LOCK_SERIAL_PORT=/dev/serial/by-id/usb-FTDI_FT232R_USB_UART_A96TPRFZ-if00-port0
```

`LOCK_MODBUS_ADDR=2:後門,3:前門` 未動。
備份留在現場 `.env.bak.20260903`。

**兩條匯流排互不影響**（已驗證）：
- 電子鎖 addr 2/3 → **USB-485**（`.env` 的 `LOCK_SERIAL_PORT`）
- PD3R3 IO addr 1 → **THS2**（systemd 的 `Environment=IO_PORT=/dev/ttyTHS2`）

—— 鎖已被拆離 THS2，證實改接屬實。

**切換後（走 USB-485）**：

| 前門 | 3 | ✅ true | 門磁斷開(門開) | 已上鎖 | 在位 |

> 前門顯示門開、並在 14:53 觸發「箱門未關 (>30秒)」告警 ——
> 與現場人員仍在作業一致，不是誤判。

**PD3R3 IO（addr 1）仍正常**：`connected: true`、DI0-2 讀得到、
DO1「運作狀況」綠燈亮、`comm_ok: true`、`auto_mode: true`。

**0xC000 開鎖記錄讀取通道成立**：重啟後 io_daemon 自動清空啟動前積壓 ——
```
鎖#2 清空啟動前積壓:成功 20 失敗 31
鎖#3 清空啟動前積壓:成功 31 失敗 18
```
能成功讀出記錄代表 0xC000 指令在 USB-485 上可用（走 THS2 時讀不到，
這正是改接的主要目的）。失敗的部分是積壓中的空槽/壞幀，屬正常。

## 五、⚠️ 尚未驗證：真實卡號

`lock_events` 至今 365 筆，**`card_no` 有值的是 0 筆**。

原因是切換後還沒有人實際刷卡 —— 啟動時清掉的積壓記錄是切換前的舊資料，
不會回填卡號。**要現場刷一次卡才能確認卡號真的讀得到。**

驗證方式：
```bash
# 現場刷卡後
sqlite3 data/violations.db \
  "select datetime(created_at,'localtime'),lock_addr,event_type,card_no,holder_name \
   from lock_events order by id desc limit 5"
```
`card_no` 有值即為成功。若仍為 NULL，要回頭查 0xC000 解析而非通訊層
（通訊層已由上面的積壓清空證實可用）。
