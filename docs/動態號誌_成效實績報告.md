## 一、先講結論

**可以證明的**：系統確實在控制路口，控制是安全的，而且每一次下發都可回溯。

**不能主張的**：「比原本的控制好」。**現有資料無法支持任何成效比較**，
原因有兩個，任何一個單獨成立就足以否定比較（第四節）。

> 🛑 這份報告刻意不給「延滯改善 X%」這種數字。給得出來的只有
> 「我方控制期間量到多少」，那是**現況基準**，不是成效。
> 把基準寫成成效，是這類報告最容易犯、也最難被發現的錯。

| 時間 | 級數 | 類別 | 原因 |
|---|---|---|---|
| 09-08 01:10:35 | L2 | 指令傳輸錯誤 | 連續 6 次下發送不出去（daemon 500），持續逾 60 秒確認 |
| 09-08 14:34:12 | L2 | 偵測器故障 | 分相 1、2 的排隊與流量都取不到，持續逾 60 秒確認 |
| 09-08 22:53:58 | L0 | 服務重啟 | 上一段降階在重啟時關閉 —— **實際恢復時刻不明** |
| 09-09 19:05:22 | L2 | 指令傳輸錯誤 | 連續 15 次下發未被接受（無 ACK 或 NAK），持續逾 60 秒確認 |
| 09-09 19:44:38 | L0 | 故障排除 | 自動復歸，該段降階 39.3 分鐘 |

**降階時我方做的事是「不做事」**：停止 `5F10` 續約，授權一分鐘內過期，
控制器自行回到內建時制。不靠送命令回復，靠不送。

🛑 **09-08 14:34 那一段的長度無法計算。** 降階狀態存在記憶體，服務重啟會回到
L0，所以紀錄只能寫到「重啟時關閉」。那段究竟持續多久、期間路口跑什麼，
**這份資料答不出來**，不要拿它去湊「降階總時數」。

## 四、為什麼不能主張成效

### 理由一：沒有 A/B 交替時段

我方在 09-07 之後幾乎全時控制，之前完全沒有。跨日比較「有控制 vs 沒控制」
等於把**日期差異**（車流、天候、事件）整包算進控制的效果。

要主張「優於現行控制」，唯一站得住的作法是**同一天內交替**
（例如每小時輪替我方／控制器內建），讓兩組樣本共享同樣的外在條件。
現階段沒有做過這件事。

### 理由二：`throughput_vph` 這個指標跨日不可比

逐日比對「原始量測」與「衍生指標」：

| 日期 | 原始 flow 平均（輛/分） | `throughput_vph` | flow 量不到的比例 |
|---|---|---|---|
| 09-04 | 26.7 | 1,061 | **74.8%** |
| 09-05 | 19.2 | 873 | 0.2% |
| 09-06 | 16.7 | **245** | 0.0% |
| 09-07 | 27.7 | 341 | 0.6% |
| 09-08 | 14.1 | 227 | 0.0% |
| 09-09 | 17.4 | 291 | 0.0% |

**原始流量從 09-05 到 09-06 只降 13%，衍生的通過量卻掉了 72%。**
兩者不成比例，代表落差來自指標本身的計算或前提改變，不是路上的車變少。

而且 **09-04 有 74.8% 的樣本根本量不到流量** —— 那天的 1,061 輛/小時
是用四分之一的樣本算出來的，不能當基準。

🛑 落差發生在 **09-06**，而我方第一次下發是 **09-07 21:38** ——
**在我方開始控制之前就掉下去了**。這同時證明兩件事：
落差不是我方造成的；以及這組數列不能用來做前後比較。

### 附帶：一致率在下發之後已失去驗證意義

「我方判斷 vs 實際換相」的一致率，在**只比對不下發**的期間是有效的驗證
（2026-09-03 的比對報告：整體 87.4%、尖峰 54.7%）。
但我方開始下發之後，實際換相有一部分**就是我方造成的** ——
此時的高一致率是循環論證，不能拿來說「演算法判斷準確」。

## 六、要能主張成效，需要做什麼

1. **A/B 交替時段**：同一天內以固定週期輪替「我方控制」與「控制器內建時制」，
   至少涵蓋數個工作日的同一時段，讓兩組樣本共享外在條件。
   後端已有 `/shadow/outcome/compare` 可比兩段，缺的是**排程輪替**本身。
2. **釐清 `throughput_vph` 的計算前提**，確認它在期間內定義未變；
   在那之前，成效指標以延滯與排隊為主。
3. **降階紀錄要能跨重啟保存進行中的區段**，否則「降階總時數」永遠缺一角。

## 附錄：資料如何取得（可複驗）

```sql
-- 下發次數與逐日
SELECT date(ts,'unixepoch','localtime') d, COUNT(*)
FROM signal_frames WHERE src='self' AND code='5F1C' GROUP BY d;

-- 控制器回應(以 seq 逐筆配對,不用時間鄰近推定)
SELECT code,raw FROM signal_frames
WHERE src='controller' AND code IN ('0F80','0F81') AND seq=? AND ts BETWEEN ? AND ?;

-- 逐時評估
SELECT hour,samples,cycles,delay_per_veh,throughput_vph,queue_eval_m
FROM signal_hourly_eval ORDER BY hour;

-- 原始量測(用來檢查衍生指標是否可比)
SELECT substr(ts,1,10) d, AVG(flow_vpm_1), AVG(flow_vpm_2),
       SUM(CASE WHEN flow_vpm_1 IS NULL THEN 1 ELSE 0 END)*1.0/COUNT(*)
FROM signal_shadow_log GROUP BY d;
```
