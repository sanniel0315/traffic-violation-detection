# 動態號誌控制 — 視覺設計統一 PLANNING

> 2026-09-05。針對三處：即時決策盤、控制策略旗標、分相時間分配圖。
> 統一原則寫在第一節，三處的做法在後面各一節。

---

## 一、統一原則（三處共用）

### 1. 一頁只能有一個主角

每張卡先回答「現在怎樣」，細節排在後面。目前決策盤的毛病是**判定結果被放在
card-header 的小 tag 裡** —— 最重要的結論字級最小、位置最邊緣，而四張表格
以完全相同的權重平鋪。看的人得自己找重點。

### 2. 對抗關係要用「對抗的形狀」畫，不要用表格

號誌決策的本質是兩股力量在拉：**紅側等太久了該換** vs **綠側還在放行別浪費**。
表格把它攤成兩欄數字，讀的人要在腦裡做減法才知道差多少。改用同一把尺的
兩條對抗條，差距是看出來的不是算出來的。

同理，控制策略 8 位元是「哪幾個同時亮」的狀態，分相時制是「一輪 85 秒怎麼
分配」的比例 —— 兩者都是空間關係，都該用圖不用表。

### 3. 數字保留、可稽核不打折

美化不等於簡化。這一頁存在的理由就是**接管控制權之前每一項都要能追回量測值**，
所以算式、常數、原始值一項都不能刪，只是收進次級層次（副值、hover、摺疊）。

### 4. 動畫只用來表達「狀態變了」

不做裝飾性動畫。允許的只有三種：
- **脈動** = 這一項現在正在生效（控制策略亮著的位元、決策天平的優勢側）
- **變化閃爍** = 這個值剛剛改變（策略位元翻轉時閃 1.2 秒）
- **長度過渡** = 條狀圖的數值變動用 transition，不要跳

`prefers-reduced-motion` 一律關掉。

### 5. 色彩語意固定，跨三處一致

| 顏色 | 語意 | token |
|---|---|---|
| 綠 | 綠燈側／通行／正常 | `--gov-ok` |
| 紅 | 紅燈側／全紅／異常 | `--gov-fault` |
| 琥珀 | 黃燈／警示／強制 | `--gov-warn` |
| 政府藍 | 我方系統的判定與強調 | `--gov-primary` |
| 灰 | 未生效／未觸發 | `--gov-mute-2` |

🛑 紅色在這一頁有兩個意思（紅燈相位 vs 異常），會混淆。規則：
**燈色只出現在燈態相關元件**（分相色帶、兩側對照卡的左緣），
**警示紅只出現在狀態標籤**。兩者不共用同一個元件。

## 二、即時決策盤

### 現況問題

1. 判定（續綠／應換相）在 header 小 tag，最重要卻最不顯眼
2. 四張表格平鋪，沒有層級
3. 「裕度 −24.11」沒有比例尺，看不出差多少、離門檻多遠
4. 安全閘門四條靜態列，看不出「依序判定、先中先生效」的流程
5. **量測相機顯示 ID3／ID4** —— 相機已改用現場名稱 NE-2／WN-1，這裡沒跟上（真 bug）

### 重做

**(a) 決策天平**（新增，放在最上面）

```
判定  續綠                                    裕度 −24.1 車·秒
換相力  ▓▓░░░░░░░░░░░░░░░░░░░░  0.0
續綠力  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓  24.1   ← 綠側價值 22.5 + 換相成本 1.6
```

兩條共用同一把尺（max = 兩者較大值 × 1.15），優勢側脈動。
一眼看出「差 24 車·秒」而不是「−24.11 是多少」。

**(b) 兩側對照卡**取代 8 列表格

左右兩張卡，左緣色條標燈色（綠側綠、紅側紅）。卡內：
- 主數字：排隊長度 m（大字）＋ 換算車輛
- 佔用比進度條：對儲車上限，超過 80% 轉琥珀（主線保護門檻）
- 副資訊：到達流量、量測相機**名稱**（NE-1/NE-2/WN-1/WN-2）、主線保護 badge

**(c) 安全閘門改橫向 stepper**

四關依序排開，生效的那一關高亮並標「生效」，它前面的標「通過」，
後面的標「未評估」—— 因為先中的先生效，後面根本沒跑到。
目前四條都寫「未觸發」是錯的表達：第 4 關明明生效了。

**(d) 算式與常數**保留原表，收到「拆解與參數」摺疊區內，預設收合。

## 三、控制策略旗標（8 位元互動動畫）

### 現況

一個 `el-tag` 印 `14H 路口手動+時相控制`。八個位元的狀態被壓成一行字串，
看不出「哪些亮、哪些暗」，也看不出剛剛翻轉了哪一位。

### 重做

八個 chip 一字排開，每個顯示位元名稱與 bit 編號：

- **亮**：實心政府藍＋左側圓點**脈動**
- **暗**：灰底、低對比
- **剛翻轉**：閃爍 1.2 秒（前後值比對，只標真的變的那幾個）
- **hover**：顯示這個位元的意思

旁邊保留原始值 `0x14`，可稽核。

🛑 特別標註 bit2（路口手動）與 bit4（時相控制）：OPAC 接管時**兩個一起寫**，
只看 bit2 會誤判成「被切手動」—— 這是 2026-09-02 現場實測踩過的坑，
說明文字要寫在 hover 裡，不能只留在程式註解。

同一個元件用在兩處：決策盤的「控制權現況」與燈態的「安全網」。

## 四、分相時間分配圖

### 現況

只有 `tp-tbl` 純表格：分相 / 綠燈 / 最短綠 / 最長綠 / 黃燈 / 全紅 / 人閃 / 人紅。
「一輪 85 秒怎麼分」要自己心算。

### 重做

每套時制計畫展開後，表格**上方**加一條色帶圖：

```
0        20        40        60        80  (秒)
├─────────┼─────────┼─────────┼─────────┤
分相1  ██████████████▓▓░░  ·············    35 綠 3 黃 2 全紅
       行人 ▓▓▓▓▓▓▓▓▓▓▒▒▒  ·············
分相2  ·············  ██████████████▓▓░░    40 綠 3 黃 2 全紅
       行人 ·············  ▓▓▓▓▓▓▓▓▓▒▒▒
```

- 每分相一列，段寬 = 秒數 ÷ 週期
- 段別：綠燈（綠）／黃燈（琥珀）／全紅（紅）／其餘為紅燈（灰點）
- 行人另一條細軌：行人綠／綠閃（斜紋）／行人紅
- 頂部時間刻度，末端標各段秒數
- hover 顯示該段名稱與秒數

🛑 資料缺項不補 0：控制器沒回報的欄位畫成斜線區並標「未回報」，
不可以畫成 0 秒 —— 「沒查到」跟「真的是 0」是兩件事，這一頁到處都在守這條。

資料來源 `/api/signal/timing-plans`（`_merge_timing_plans`，已有
green / min_green / max_green / yellow / all_red / ped_flash / ped_red / cycle）。

## 五、實作順序

1. 控制策略 8 旗標元件（最小、兩處共用，先做可立刻驗證動畫規則）
2. 決策盤天平 + 兩側卡 + stepper
3. 分相時間分配色帶

每一步後跑 `web/index.html` 的三道 SOP：div 平衡、模板 lint、`node --check`。
