### 操作通則（所有設定頁共用）

多數設定頁採同一套安全流程：

```
選路口 → 回讀現值 → 編輯 → 送出 → 差異確認(DiffConfirmDialog) →
高影響操作確認(勾「我已確認並了解此操作之影響」) → 回讀驗證(逐欄比對 預期/實際/結果)
```

- **未選路口**時顯示「尚未選擇路口」，多數操作需先在左側選 `deviceUid`。
- **高影響操作**（下發控制器、遠端重啟、手動校時）一律跳確認框。
- **回讀驗證**：送出後重新查詢，逐欄比對「欄位／預期值／實際值／結果」，`switched`=生效、`notEffective`=回讀不符。
- **民國年**：ROC = 西元 − 1911；時間顯示 UTC+8。

## 一、動態號誌控制邏輯（跨系統整條迴路）

這是整套系統的核心。**控制策略是 TC3 協定的一個位元組（8 個 bit）**，`/sig` 系統的 8 個布林旗標就是這 8 個 bit：

```
bit0 定時控制 0x01 fixTime        bit4 時相控制 0x10 phase
bit1 動態控制 0x02 dynamic        bit5 即時控制 0x20 realtime
bit2 路側手動 0x04 roadSideManual bit6 觸動控制 0x40 trigger
bit3 中央手動 0x08 centerManual   bit7 特勤路線 0x80 specialRoute
```

（對照 Jetson `api/routes/signal_tc3.py` 的 `STRATEGY_BITS`，同一份定義。）

### 控制迴路

```
┌────────────────────┐  TC3 5F10 控制策略      ┌──────────────────┐
│ /sig 號誌管理系統   │  TC3 5F15 時制計畫       │  號誌控制器       │
│ 10.42.38.35        │ ─── 下發 ───────────►  │  (RS-232)        │
│ (設定/下發介面)     │                          └────────┬─────────┘
└────────────────────┘                                   │ 5F+03 主動回報
                                                          │ (時相/燈態)
   dynamic=true 時,配時改由                                ▼
   邊緣端演算法接管                         ┌────────────────────────────┐
        Jetson = 動態演算本體               │ MiiNePort 10.42.40.222      │
        (車流/佔用率/排隊 → 配時)           │ → Jetson signal_tc3.py 抄錄  │
                                            │   (唯讀監看,下傳預設關閉)     │
                                            └────────────────────────────┘
```

### 動態模式的意義

- **定時模式（fixTime）**：控制器依固定時制表運作，配時不變。
- **動態模式（dynamic）**：`bit1` 打開後，配時不再走固定時制表，改由**動態演算法接管**——本站演算本體是 Jetson，用車流偵測（佔用率、排隊長度、停等）即時算綠燈配時。啟用時必填 `effectTime`（有效時間，秒，0–65535）。
- 現場 SIG-01 現況：`fixTime + roadSideManual`（定時＋路側手動），動態未啟用。

> 🛑 **切換動態模式會改變真實路口號誌運轉**（送出 TC3 5F10）。這是不可逆的現場動作，須經高影響操作確認。

## 三、功能頁逐項說明

每一節格式：**用途 → API → 欄位 → 操作 → 作用**。

### 1. 控制策略 `/control-strategy`〔號誌設定〕

- **用途**：切換路口的運作策略旗標（可多選），決定由誰／哪套邏輯接管配時。
- **API**：`GET /control-strategy/{deviceUid}` 回讀｜`POST /control-strategy` 下發（cmdId `5F10`）
- **欄位**：8 個布林旗標（見第一節）＋ `effectTime`（動態有效時間，秒）。預設 `fixTime=true`。
- **操作**：重新查詢 → 勾選策略 → 送出（跳「控制策略變更確認」）→ 回讀驗證。
- **驗證**：`atLeastOne`（至少選一種）；`effectTimeRequired`（啟用動態時須填有效時間）。
- **作用**：例如勾 `dynamic` 並填有效時間，該路口切到動態模式由邊緣端演算法配時。
- **實機現況**：`{fixTime:true, dynamic:false, roadSideManual:true, …, effectTime:0}`

### 2. 時制計畫 `/timing-plan`〔號誌設定〕

- **用途**：編輯與下發某計畫編號的基本參數與各分相秒數，並可切換目前執行中的計畫。
- **API**：
  - `GET /timing-plan/params/{deviceUid}?planId=`（基本參數 5F14）
  - `GET /timing-plan/content/{deviceUid}?planId=`（計畫內容 5F15）
  - `GET /timing-plan/executing/{deviceUid}`（目前執行中計畫）
  - `POST /timing-plan/params`（5F14）｜`/content`（5F15）｜`/execute`（5F18 切換執行）
- **欄位（計畫層）**：`planId`、`direct`（計時方向 0–7）、`phaseOrder`（時相排列碼）、`subPhaseCount`、`cycleTime`（週期秒）、`offset`（時差秒）、`subPhases[]`。
- **欄位（子分相）**：`subPhaseId`、`green`、`yellow`、`allRed`、`pedGreenFlash`、`pedRed`、`maxGreen`、`minGreen`。
- **操作**：查詢、複製來源計畫、新增/刪除分相、送出基本參數、送出計畫內容、執行此計畫、列印。含「分相時間分配圖」色帶。
- **驗證**：
  - `cycleMismatch`：綠+黃+全紅 須等於週期（可勾強制送出）
  - `minGreenViolation`：minGreen < maxGreen
  - `subPhaseCountMismatch`：控制器回報分相數與宣告不符（如實呈現不補齊）
- **特殊計畫**：`0`動態／`47`鐵路／`48`基本 僅可查詢與執行、不可編輯。切換執行前先載入內容預覽，載入失敗則拒絕執行（不盲切）。
- **作用**：下發後控制器改用該計畫配時；執行切換改變當前套用的計畫編號。

### 3. 號誌運作狀態 `/signal-runtime`〔即時監看｜唯讀〕

- **用途**：控制器**現值權威來源**——目前模式、執行中計畫、目前分相、週期進度、各方向燈態，經 WebSocket 即時更新。
- **API**：初值走 REST + WebSocket `/websocket` 訂閱即時燈態（步階轉換 5F03）。
- **欄位**：`controllerId`、`operatingMode`、`executingPlan/planId`、`subPhase`、`comm`（連線正常/中斷/初值查詢失敗）、`cycleTime`、`stepSeconds`、`signalCount`、`phaseOrder`；週期進度條 `{elapsed}s/{cycle}s`。
- **方向卡片**：依方向畫燈色（紅/黃/綠/左綠/直行綠/右綠/行綠/行紅）＋路口示意圖。
- **操作**：重新整理（唯讀，無下發）。
- **作用**：即時監看。註：本頁為控制器現值，與「運作統計」頁（來自 AI 統計服務）來源不同、數值可不一致屬正常。
- **維運提示**：逾時未收到回報→檢查反向代理是否轉發 `/websocket` upgrade、該路口步階轉換傳輸週期是否被設為「停止」。

### 4. 時相排列 `/phase-order`〔號誌設定〕

- **用途**：設定某時相類型編號的各分相第一步階燈態與方向對位。
- **API**：`GET /phase-order/{deviceUid}?phaseOrder=`｜`POST /phase-order`（cmdId `5F13`）
- **欄位**：`phaseOrder`（0–254，白名單）、`signalCount`（岔路數）、`subPhaseCount`、`signalMap`（八方位 0/1）、`signalStatusList[]`（長度 = subPhaseCount × signalCount，每格 8 燈布林 red/yellow/green/leftGreen/straightGreen/rightGreen/pedestrianGreen/pedestrianRed）。
- **操作**：輸入時相碼查詢、新增/刪除分相、送出、回讀驗證。
- **規則**：燈態依「北起順時針」對位；同岔路「行綠+行紅」同勾＝行人綠閃；本頁僅設第一步階，其餘步階由 5F14 決定。
- **作用**：定義相位輪替的燈色組合與方向指派。

### 5. 觸動控制 `/actuated-control`〔號誌設定〕

- **用途**：設定感應式（觸動）控制參數，並即時監看觸動回報。
- **API**：`GET /actuated-control/{deviceUid}`｜`POST /actuated-control`
- **欄位**：`actuateType`（觸動種類）、`subPhaseId`（1–8）、`timeExtend`（延長延時秒 0–255）、`actuateData1`、`actuateData2`（0–255）。
- **觸動種類**：`0`清除／`1`公車／`2`左轉／`4`匝道／`8`鐵路／`16`行人／`32`全觸動／`64`竊盜車輛。
- **參數語意（依種類）**：公車→data1 延長上限、data2 延長下限；左轉→data1 觸動時相編號；匝道→data1 紓解秒數；行人→data1 綠燈起始秒數。
- **操作**：查詢、送出（跳「觸動控制組態變更確認」）、回讀驗證；即時面板「觸動進行回報」。
- **作用**：啟用/設定觸動邏輯（如公車優先延長綠燈、行人觸動）。
- **實機現況**：`{subPhaseId:0, actuateType:0, timeExtend:0, cleared:true}`（未設定）

### 6. 時段型態 `/segment-type`〔號誌設定〕

- **用途**：設定「一般日」或「特殊日期段」的時段時制排程（何時段套用哪個計畫）。
- **API**：`GET /segment-type/normal/{deviceUid}`｜`/special/{deviceUid}`｜`POST /segment-type/normal`（5F16）｜`/special`
- **欄位**：`segmentType`（一般日 1–7／特殊日 8–20）、`numWeekDay/weekDays`（1–7 週一~日、11–17 隔週）、`segmentCount`（1–32，0=清除/預設）、`segments[]`（每段 `{hour, min, planId}`）；特殊模式另含 `startDate/endDate`。
- **操作**：查詢（一般日須同時指定時段型態碼＋查詢週內日）、新增/刪除分段、送出、清除特殊日期段（segmentCount=0）、回讀驗證。
- **規則**：分段時間須遞增不重疊不缺值；一般日 segmentCount=0＝執行預設時制（非清除，與特殊日的 0 語意不同）。
- **作用**：規劃一天內不同時段自動切換時制；特殊日期段可在指定日期區間套用專用時制。

### 7. 傳輸週期 `/transmit-cycle`〔號誌設定〕

- **用途**：設定控制器主動回報資料的頻率。
- **API**：`GET /transmit-cycle/{deviceUid}?transmitType=`｜`POST /transmit-cycle`（cmdId `5F3F`）
- **欄位**：`transmitType`（`1`燈態傳輸 5F0F／`2`步階轉換 5F03）、`transmitCycle`（`0`即時／`1`每1秒／`2`每2秒／`3`每5秒／`4`每1分／`5`每5分／`255`停止）。
- **操作**：查詢、送出（跳「傳輸週期變更確認」）、回讀驗證。
- **作用**：調整即時資料回報頻率，影響即時監看與統計取樣密度。
- **提示**：週期越短越即時、統計樣本越密；無線通訊僅接受「變動即回報」與「每5分鐘」。

### 8. 時間偏差總覽／校時 `/time-sync`〔即時監看〕

- **用途**：總覽各路口控制器時間偏差，異常時手動校時（NTP 為設備自動行為，本頁輔助不取代）。
- **API**：`GET /time-sync/overview`（總覽）｜`POST /time-sync/manual`（手動校時）
- **總覽欄位**：`intersectionName`、`deviceUid`、`status`（NORMAL/WARNING/PENDING/ERROR）、`offsetSeconds`、`thresholdSeconds`、`allowedMin/Max`、`checkedAt`。分頁 10 筆。
- **手動校時**：
  - 模式一「以 TCIS 主機系統時間校正（建議）」：送 `year=0`，由 icAgent 主機校正。
  - 模式二「手動指定日期時間」：民國年 0–255、月 1–12、日、時 0–23、分 0–59、秒；含「民國/西元/週幾」即時預覽。
- **操作**：重新整理、（每列）校正、送出校時（跳高影響確認）。
- **作用**：手動校正控制器時鐘。
- **實機現況**：SIG-01 `status=PENDING`（等待回報中，取時來源待 TCIS 介接）。

### 9. 特勤路線（VIP） `/vip-route`〔號誌設定〕

- **用途**：設定特勤/優先路線（綠波），指定進入/離開方向與執行時段，或解除。
- **API**：`GET /vip-route/{deviceUid}`｜`POST /vip-route`（都三 5F1E）
- **欄位**：`entryDirection`（進入方向 0–7）、`exitDirection`（離開方向 0–7，`8`=停止）、`startHour/startMin`、`endHour/endMin`。預設 進2東/出6西/08:30–09:00。
- **執行模式**：`ffh` 強制執行（四時間參數＝255）立即強制／`scheduled` 按排程時間。
- **解除**（direct=8）：`releaseForce`（帶 255）解除強制／`releaseScheduled`（帶 00:00）解除排程；停止時離開方向由系統帶「停止」。
- **特殊規則**：通訊斷線現場自動解除「強制執行」；恢復時不自動回復。
- **操作**：查詢、送出（跳「特勤路線參數變更確認」）、回讀驗證。
- **作用**：為特勤車隊建立路線綠波優先。

### 10. 設備狀態 `/device-status`〔即時監看〕

- **用途**：顯示控制器各故障位元/健康狀態，可設定狀態回報週期與遠端重啟。
- **API**：`GET /device-status/{deviceUid}`｜`POST /device-status/{deviceUid}/report-cycle`（0F04）｜`POST /device-status/{deviceUid}/restart`（遠端重啟）
- **健康狀態位元**（16 位，實機實測）：
  - 處理器/記憶體：`cpuModuleError`、`memoryError`、`timerError`、`watchdogTimerError`
  - 電源：`powerError`（AC 80~130V 之外）、`signalPowerError`
  - 號誌燈：`signalDriverUnitError`、`signalHeadError`、`signalConflictError`（號誌衝突）
  - 通訊：`communicationConnect`、`commLineBad`
  - 時制：`timingPlanError`、`timingPlanOnTransition`、`controllerReady`
  - I/O/機箱：`ioUnitError`、`cabinetOpened`（機箱門開啟）
- **回報週期**：`0`變動即回報／`1`每1秒／`2`每2秒／`3`每5秒／`4`每1分（出廠預設）／`5`每5分。
- **操作**：只看異常、回報原文、設定回報週期、遠端重啟控制器（跳高影響確認：重啟期間短暫中斷）。
- **作用**：故障監控 + 調整回報頻率 + 遠端重啟。
- **實機現況**：SIG-01 `controllerReady=true`，其餘位元皆 false（無故障）。

### 11. 運作統計 `/stats`〔歷史與統計〕

- **用途**：呈現路口運作 KPI、綠燈時間統計、綠燈秒數趨勢、歷史時制調整與故障情形。
- **資料來源**：AI 適應性控制服務之號誌統計（**非控制器現值權威**）。需在設備組態設 `statsIntersectionId`（如 N8-E-9），未設則無資料。
- **即時狀態列**：運作狀態、控制狀態、綠燈方向、已亮綠燈/上下限、決策間隔。
- **KPI 卡**：相位切換次數、強制切換次數（佔比）、每綠燈秒通過車輛、出口滯留車輛/長度、故障總計（AICCTV 累計失敗＋iCAgent 命令失敗＋狀態不符）。
- **綠燈統計（依方向）**：樣本數、平均綠燈秒、變異數、標準差、車輛/綠燈秒。
- **趨勢圖**：綠燈秒數趨勢（可能截斷「最近 N 筆」）+ 強制切換標記；歷史時制調整紀錄；故障情形（AICCTV 延遲/連續失敗、iCAgent 命令失敗、狀態不符）。
- **操作**：查詢、匯出 CSV（需後端）、列印、即時更新（需後端）。
- **作用**：績效分析與故障統計。資料不足時明確標示，不以 0 代表實際統計。

### 12. 異動紀錄 `/changes`〔歷史與統計〕

- **用途**：查詢設定異動歷史、標記已讀、對單筆回讀控制器現值。
- **API**：`GET /change/list`（列表）｜`GET /change/readback`（回讀現值）｜`POST /change/unread/read`（全部標已讀）｜`GET /change/unread/count`（未讀數）
- **列表欄位**：`reportedAt`、`category`、`deviceUid`、`sourceReport`、`changedItem`。
- **明細**：`subDbId`、`referencedCmdId`、`rawPayload`（回報原文）、`currentValue`（經回讀的現場實際設定）。
- **異動類別**：PHASE_ORDER 時相排列／TIME_SEGMENT 時段型態／BASIC_PARAMETER 基本參數／TIMING_PLAN 時制計畫／VIP_PARAMETER 特勤參數／REVERSE_LANE_CONTROL 調撥控制／DIM_CONTROL 減光控制／ACTUATED_CONTROL 觸動控制／FIELD_OPERATION 現場操作模式／UNCLASSIFIED 未分類。
- **操作**：類別/時間篩選、查詢、匯出 CSV（需後端）、全部標已讀、回讀現值（部分類別「無對應查詢指令，不支援回讀」）。
- **保留**：異動/操作紀錄保留 180 天。
- **作用**：稽核追蹤所有下發變更。
- **實機現況**：目前未讀 25 筆；列表中有 `deviceUid:"UNKNOWN"` 的紀錄。

### 附. 設備組態 `/device-registry`〔系統〕

- **用途**：路口/設備的 CRUD，是其他頁面的資料來源。
- **欄位**：`deviceUid`（識別碼，**建立後不可變更**）、`intersectionName`、`deviceName`、`ipAddress`（合法 IPv4）、`port`、`controllerDeviceId`（回報設備識別，如 253-7；未填則收不到即時燈態與統計）、`statsIntersectionId`（統計路口對照，如 N8-E-9；未填則統計無資料）、`enabled`、八方位路名 `approachRoads`。
- **操作**：新增、編輯、刪除（路口自選擇器消失但既有紀錄保留 180 天）、儲存。

## 附錄：與 Jetson 交通分析系統的關係

- 本系統（`/sig`）是**號誌設定/下發**介面；Jetson `traffic-violation-detection` 是**車流分析 + 動態演算本體**。
- 動態模式啟用時，Jetson 用車流偵測（佔用率、排隊長度、停等判定）算配時。
- Jetson `api/routes/signal_tc3.py` 負責 TC3 抄錄與監看（下傳預設關閉，須 `SIGNAL_TC3_CONTROL=1` 才啟用）。
- 兩套系統共用 TC3 控制策略位元定義（見第一節）。
