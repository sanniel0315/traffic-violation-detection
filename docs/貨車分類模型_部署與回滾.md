# 貨車分類模型（truck_cls）部署與回滾

車種細分類模型（大貨／小貨／大客／小客）的換模型、驗證、回滾程序。
模型檔**不在 git 裡**，換模型是現場手動操作，所以流程寫在這裡以免失傳。

## 路徑鏈

```
.env: MODEL_DIR=/workspace/models
  /workspace                     -> symlink 到 /home/ubuntu/traffic-violation-detection
  <repo>/models                  -> symlink 到 /mnt/nvme/traffic/models   ← 真實檔案在這
```

實際檔案三件一組（程式優先吃 `.engine`，見 `detection/truck_classifier.py`）：

| 檔案 | 用途 |
|---|---|
| `truck_cls_yolo26s.pt` | 訓練產出的權重，engine 的來源 |
| `truck_cls_yolo26s.onnx` | 中間產物 |
| `truck_cls_yolo26s.engine` | **實際跑的** TensorRT FP16 engine |

### CI deploy 不會洗掉模型（2026-09-03 查證）

- `/models` 列在 `.gitignore` → 未追蹤，`git reset --hard origin/main` 不動它
- `.github/workflows/` 內**沒有 `git clean`** → symlink 不會被刪
- 真實檔案在 `/mnt/nvme/traffic/models/`，在 repo 之外

deploy 會 `systemctl restart traffic-api`，重啟後從同一路徑重新載入 → 現場模型維持不變。
🛑 若日後有人在 workflow 加 `git clean -xfd`，這層保障就破了。

## 換模型 SOP

```bash
# 0) 權重上傳到 87
scp best.pt ubuntu@100.92.17.87:/mnt/nvme/new_model.pt
ssh ubuntu@100.92.17.87 "md5sum /mnt/nvme/new_model.pt"   # 與本機比對

# 1) 備份現行三檔（標記用途，不要覆寫既有備份）
ssh ubuntu@100.92.17.87 "cd /mnt/nvme/traffic/models && \
  for f in pt onnx engine; do cp -p truck_cls_yolo26s.\$f truck_cls_yolo26s.\$f.before_XXX; done"

# 2) 在暫存目錄建 FP16 engine（🛑 不要直接在正式目錄建，失敗會留下壞 engine）
ssh ubuntu@100.92.17.87 "mkdir -p /mnt/nvme/build && \
  cp /mnt/nvme/new_model.pt /mnt/nvme/build/truck_cls_yolo26s.pt && \
  LD_LIBRARY_PATH=/home/ubuntu/.local/lib/python3.10/site-packages/nvidia/cusparselt/lib \
  python3 -c \"
from ultralytics import YOLO
YOLO('/mnt/nvme/build/truck_cls_yolo26s.pt', task='classify').export(
    format='engine', half=True, imgsz=224, device=0)\""
# 約需 7 分鐘

# 3) 驗證 engine 與 .pt 判斷一致（一致率應 >95%，FP16 量化會有少量差異）
#    🛑 一定要逐張推論，engine 是 batch=1 固定，餵 batch>1 會 AssertionError

# 4) 覆蓋正式檔並重啟
ssh ubuntu@100.92.17.87 "cd /mnt/nvme/traffic/models && \
  cp /mnt/nvme/build/truck_cls_yolo26s.{pt,onnx,engine} . && \
  chmod 600 truck_cls_yolo26s.pt && sudo systemctl restart traffic-api"

# 5) 確認載入無誤
ssh ubuntu@100.92.17.87 "sudo journalctl -u traffic-api --since '3 min ago' --no-pager \
  | grep -a TruckClassifier"
# 應出現：⚡ TruckClassifier 切換到 TensorRT engine: /workspace/models/truck_cls_yolo26s.engine
```

## 已知地雷

| 地雷 | 說明 |
|---|---|
| **engine 是 batch=1 固定** | 餵 batch>1 直接 `AssertionError: input size ... not equal to max model size (1,3,224,224)`。合批最佳化不要再試（2026-08-18 有事故紀錄）。 |
| **Jetson torch 需 LD_LIBRARY_PATH** | 少了會 `ImportError: libcusparseLt.so.0`。路徑：`/home/ubuntu/.local/lib/python3.10/site-packages/nvidia/cusparselt/lib` |
| **engine 建置吃 GPU** | 與線上推論競爭，宜離峰執行。 |
| **`.pt` 權限是 600** | 覆蓋後補 `chmod 600`。 |

## 模型評估方法

換模型前必須做 A/B。**不要用 `dataset_field_0828` 的 val/test 單獨下結論**——樣本太少（light 僅 86 張）
且與訓練資料同源，會有「同一台實體車拿到不同 track_key 而被切到不同 split」的洩漏。

正確做法是**歧異抽樣**：只人工標註「新舊模型判斷不同」的 track（判斷相同的部分對勝負無貢獻，
會互相抵銷），各歧異類型內隨機抽並記錄母體數，用權重還原到全母體，即可得到
「淨變化 ±X 個百分點」與信賴區間。約 600～700 條標註即可定案。
🛑 標註務必**盲標**（移掉 `predictions.json`），否則會偏袒被顯示答案的那顆模型。

腳本在 `truck_cls_dataset/`（另一個目錄，不在本 repo）：
`export_disagreement.py`（在 87 執行）、`score_disagreement.py`、`score_ensemble.py`。
